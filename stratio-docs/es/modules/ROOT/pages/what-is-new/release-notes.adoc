= Notas de _release_

Estos son los aspectos más destacados de las versiones de _Stratio Cloud Provisioner_ para los últimos lanzamientos:

== 0.9.9

* Compatibilidad con Kubernetes 1.35.
* Actualización desde la 0.7.x con el _script_ `upgrade-provisioner.py` de la imagen `cloud-provisioner-upgrade:0.9.9`, que deja el _cluster_ con Kubernetes 1.35 y _cluster-operator_ 0.7.6.
* Actualización de Cluster API (v1.10.10) y de sus proveedores: CAPA v2.9.3, CAPZ v1.21.3 y CAPG 1.6.1-0.4.3.
* Actualización de Calico y de Tigera Operator (v3.31.7), de cert-manager (v1.21.2) y de Flux (2.17.2).
* En EKS, todos los grupos de nodos se crean como _MachinePool_ (grupos gestionados por EKS), y se rechazan los grupos con _node++_++image_. _Cluster-autoscaler_ usa el proveedor `aws`.
* En EKS, se admite `deploy_autoscaler: true` con `security.aws.create_iam: false` si el rol `eks-nodegroup.cluster-api-provider-aws.sigs.k8s.io` ya tiene asociadas las políticas necesarias.
* _Cluster-autoscaler_ usa la imagen _upstream_ correspondiente a la versión de Kubernetes del _cluster_.
* Nuevos campos: `calico.observability_enabled`, que activa Whisker y Goldmane de Calico (desactivado por defecto), y `security.aws.nodegroup_extra_policy_arn`.
* Nuevo valor `BOTTLEROCKET_x86_64_NVIDIA` en el campo _ami++_++type_.

== 0.17.0-0.8.X

* Soporte de _MachinePools_ en _clusters_ EKS con _control-plane_ gestionado. Los grupos de nodos sin _node++_++image_ se aprovisionan ahora como grupos de nodos gestionados por EKS (_AWSManagedMachinePool_) en lugar de instancias EC2 autogestionadas. Un _cluster_ puede combinar ambos tipos en un mismo descriptor.
* Nuevo campo _ami++_++type_ en _worker++_++nodes_ para seleccionar el tipo de AMI del grupo de nodos gestionado. El valor por defecto es "BOTTLEROCKET++_++x86++_++64".
* Nuevo campo _mp++_++role++_++name_ en _control_plane.aws_ para asignar un rol IAM preexistente a todos los grupos de nodos gestionados, sin que _Stratio Cloud Provisioner_ cree uno nuevo.

== 0.17.0-0.6 (15 de noviembre de 2024)

* Las réplicas de CoreDNS ahora se distribuyen en nodos diferentes para mejorar la disponibilidad.
* Se crean volúmenes por defecto para containerd, etcd y la raíz del sistema si no se especifican en la configuración del _keoscluster_.
* Compatibilidad con Kubernetes 1.30. Se han marcado como obsoletas las versiones anteriores a la 1.28.
* Actualización de Tigera Operator a la versión 3.28.2.
* Se ha añadido la opción "use-local-stratio-image" para reutilizar imágenes locales.
